what it does

Bootloop Protector watches every boot. When a module or a general script stops the phone from starting, crashes the system again and again, or breaks SystemUI, it switches off the cause and reboots, so you get a working phone back without a computer or a recovery.

It does this on its own. There is nothing to press - the volume keys are only an extra option for when you want to start a rescue yourself.

Works with KernelSU, SukiSU Ultra, APatch and Magisk. It needs no internet and no other module.

what it detects
problemhow it is caught
Boot loopThe phone restarts before the boot finishes. Every boot is counted; after 3 failed boots in a row (setting) the 4th boot starts a rescue.
Stuck bootThe boot animation never ends. After the boot timeout (180 s) the phone is rebooted and the boot counts as failed.
Zygote crash loopThe boot animation starts over without a real reboot. 4 zygote restarts during boot start a rescue at once.
Soft reboot loopAfter the boot, zygote restarts 4 times within 5 minutes. A single soft reboot (done by hand or by an app) is normal and only gives SystemUI 90 s to come back.
SystemUI failureSystemUI restarts 3 times within 60 s, or stays down for 30 s. Can be switched off.

The real zygote is told apart from its freshly started children (which briefly carry the same name), so starting apps never looks like a crash.

smart rescue

Trusted setup

After a good boot the protector records every enabled module and executable general script with a fingerprint (version, boot scripts, system.prop, sepolicy.rule and the files it adds to the system). When the phone has run 10 minutes without problems (setting), that record becomes the trusted setup.

Two levels

1
Level 1 switches off only what is new or changed since the trusted setup - a module you just flashed or updated, or a new script. Almost every boot loop comes from exactly that.
2
If the problem comes back, level 2 switches off every module and general script, except the ones set to Never disable.
✕
If even that does not help, the problem is not caused by modules. The protector gives up and stops rebooting, so it can never become the reason for a loop itself.

Without a trusted setup yet (right after installing) or when nothing changed, a rescue goes straight to level 2.

The protector never switches itself off and remembers exactly what each rescue disabled.

module badges
TRUSTEDPart of the trusted setup and unchanged.
NEWNot in the trusted setup. First suspect of a level 1 rescue.
UPDATEDIn the trusted setup, but changed since. Also a first suspect.
LEARNINGNo trusted setup recorded yet.
REBOOT PENDINGInstalled or updated, active after the next reboot.
DISABLED BY RESCUESwitched off by the protector. Restore brings it back.
DISABLEDSwitched off by you.
KEPT ON RESCUESet to Never disable.
never disable

The Never disable switch next to each module and script keeps it running in every rescue, also on level 2. Use it for things the phone should always have, like a metamodule, susfs or a VPN module.

If a module set to Never disable is the cause, the protector cannot fix the loop and gives up. Switch it on only for modules you trust.

The lists are plain text files, one name per line: /data/adb/bootloop-protector/allowed-modules.txt (module ids) and /data/adb/bootloop-protector/allowed-scripts.txt (script file names).

rescue by hand

Volume Up × 3

Press Volume Up 3 times during the boot animation. The protector runs a level 1 rescue (or level 2 when nothing is new) and reboots. Handy when something is wrong that the protector does not see, like a module that makes the phone unusable but does not crash it.

Volume Down is left alone on purpose: KernelSU and SukiSU use Volume Down × 3 for their own safe mode.

From the WebUI

Disable all modules works like a level 2 rescue, so Restore all brings everything back.

From recovery

If the phone cannot get far enough to run the protector at all, flash the module zip in TWRP (or another custom recovery). It does not install anything there - it switches off all modules and general scripts and records them, so Restore works after the boot. /data must be decrypted.

after a rescue

The Status tab shows a red Rescue happened section with the time, the reason and everything that was switched off.

  • Restore all - switches everything back on. Use it after you removed or fixed the bad module, or to test again. If the problem comes back, the protector catches it again.
  • Keep disabled - closes the rescue; the items stay off until you switch them on in the root manager.

The Action button on the module card does the same as Restore all. Without a rescue it shows the status and the last log lines.

While a rescue waits for your choice, the setup is not trusted - otherwise the switched off modules would look new after a restore.

commands

Everything the WebUI does also works from a root terminal:

# status
su -c 'sh /data/adb/modules/bootloop-protector/bp.sh status'

# modules with their badges
su -c 'sh /data/adb/modules/bootloop-protector/bp.sh modules'

# bring back what the last rescue disabled
su -c 'sh /data/adb/modules/bootloop-protector/bp.sh restore'

# trust the current setup right away
su -c 'sh /data/adb/modules/bootloop-protector/bp.sh trust-now'

# never disable a module
su -c 'sh /data/adb/modules/bootloop-protector/bp.sh allow-module MODULE_ID 1'

# change a setting
su -c 'sh /data/adb/modules/bootloop-protector/bp.sh set-conf BOOT_TIMEOUT 120'

# read the log
su -c 'cat /data/adb/bootloop-protector/bp.log'

Run bp.sh without arguments for the full list.

limits
  • A module that breaks the phone before the root manager runs any script (for example a broken kernel or boot image) cannot be caught - flash the zip in recovery.
  • A hard boot loop needs the failed boots to happen first, because the phone restarts before anything can react. Lower Failed boots before a rescue for a faster reaction.
  • Changes made directly to the system partition, outside of modules, are not undone.
  • Problems that are not caused by modules or scripts end in Gave up, so the protector never keeps rebooting on its own.
